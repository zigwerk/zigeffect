# ZigEffect Testing v2 Repository Migration Design

Date: 2026-07-11
Status: accepted for implementation

## Objective

Make Testing v2 the default test execution and evidence layer for every first-party ZigEffect package and every project generated by the ZigEffect CLI. Preserve Zig's precise `std.testing` assertions while adding the information an agent needs to understand an entire test run without scraping terminal prose.

## Scope

The migration covers:

- `zigeffect` core;
- `zigeffect-std` and every standard-library namespace imported by its root test;
- `zigeffect-cli` unit and generated-project integration tests;
- `zigeffect-postgres`, `zigeffect-quic`, and `zigeffect-zio`;
- first-party ZigEffect applications and language packages `ziac` and `zgroach`;
- executable, library, and multi-service system projects emitted by `zigeffect init`;
- package-native examples that compile as tests.

Vendored third-party dependency caches are explicitly excluded.

## Design decision

Testing v2 complements rather than replaces `std.testing`.

Rewriting hundreds of low-level assertions as receipt-building scenarios would make unit tests noisier, slower, and less idiomatic. It would also force the core runtime to depend on `zigeffect-std`, creating a dependency cycle. Instead, the migration has two layers:

1. A dependency-neutral compiler test runner in `zigeffect` executes every legacy Zig test and produces a Testing v2 suite receipt.
2. The richer `zigeffect_std.Testing` package remains the API for semantic scenarios, causal assertions, schedules, models, faults, differential execution, virtual worlds, mutation, budgets, sandboxing, coverage, shrinking, snapshots, and native scenario receipts.

Thus an old `try std.testing.expect(...)` test is migrated when its test artifact uses the V2 runner. New acceptance behavior should additionally use `TestContext` and `AssertionRecorder` where semantic evidence matters.

## Runner contract

The runner must preserve the Zig 0.16 server test protocol used by `std.Build.addRunArtifact`, including:

- test metadata discovery;
- pass, skip, and failure statuses;
- allocator leak detection;
- error-log detection;
- deterministic build seed propagation;
- error return traces;
- fuzz metadata and the default fuzz execution path;
- build-system filtering and per-test reporting.

It adds a versioned, atomic JSON suite receipt under `.zigeffect/tests/suites/`. A receipt contains:

- schema and schema version;
- suite identity, Zig version, target, optimize mode, seed, and runner version;
- start/end timestamps and duration;
- one stable record per discovered test;
- pass/skip/fail, error name, error-log count, and leak count;
- totals and a completeness verdict;
- an explicit replay command and limitations.

The receipt is fail-closed: missing results, leaks, error logs, duplicate test identities, write failures, and ordinary test failures cannot be represented as a passing complete suite.

Receipt filenames are supplied by the build integration so concurrently executed test artifacts do not collide. Writes use a temporary file followed by rename.

## Build integration

Core owns the runner source and exports it as a named build module. `zigeffect-std` re-exports that runner module from its core dependency. Downstream packages obtain the runner through the dependency they already own, avoiding a runtime dependency cycle and avoiding a new runtime package.

Each first-party build file uses a small local helper that:

- sets the custom server runner on `b.addTest`;
- creates the run artifact;
- supplies a stable suite ID and receipt path;
- enables deterministic Testing v2 defaults.

Generated build files use the runner module exported by `zigeffect-std`, so a generated application needs no extra package dependency.

## Robustness additions

Every major package receives at least one semantic Testing v2 acceptance scenario where the package can depend on `zigeffect-std`. These scenarios prove package-specific boundaries rather than merely duplicating unit assertions. Core and the zio adapter use the universal runner plus existing causal/property/conformance suites because they cannot depend on the standard library.

The CLI's generated-project integration suite verifies that every scaffold:

- builds in Debug and ReleaseSafe;
- runs tests through the V2 runner;
- emits a valid, complete suite receipt;
- retains a native `TestContext` scenario receipt for manifest-owned acceptance behavior.

## Compatibility and maintenance

The runner is pinned to Zig 0.16's public build/test-server contract and carries a compatibility test. The copied protocol behavior is kept isolated from Testing v2 domain contracts, making future Zig upgrades a single bounded migration.

Documentation and both repository-owned agent skills explain the two testing layers and require suite-receipt inspection before raw terminal diagnosis.

## Acceptance criteria

The work is complete when:

1. no first-party `b.addTest` artifact in scope uses the default runner;
2. all existing tests still execute and retain their previous semantics;
3. each package test command emits a complete V2 suite receipt;
4. generated projects use the runner without an extra user-managed dependency;
5. malformed, incomplete, leaking, logged-error, and failing runs are covered by contract tests;
6. Debug and ReleaseSafe gates pass for the full local release matrix;
7. docs, templates, snapshots, and `.agents`/`.claude` skills agree.
