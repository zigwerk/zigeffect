# zigeffect Causal Tool Taxonomy Awareness Design

Date: 2026-06-07

## Problem

`CausalStore` now emits `event_taxonomy_version` and exposes typed helpers for
structural, finding-evidence, and sampleable event roles. The saved-artifact
tools still parse events as strings and ignore the taxonomy metadata. That means
an agent can read a query or compare report without knowing whether the tool
understood the event-kind semantics used by the artifact.

This matters for the self-improving development loop. Agents will increasingly
work from saved JSON, compare reports, and query reports rather than an in-memory
`CausalStore`. Those tools should make taxonomy compatibility visible.

## Goals

- Parse optional `event_taxonomy_version` in causal JSON tools.
- Warn in agent-readable output when an artifact taxonomy version is newer than
  the tool supports.
- Keep legacy event-only artifacts readable with no warning.
- Keep version `1` artifacts quiet.
- Share warning text across query, compare, and dev-loop query reports.
- Avoid changing command-line arguments or artifact shape.

## Non-Goals

- Do not reject newer taxonomy versions.
- Do not add string-level role classification for every event kind yet.
- Do not change finding-count logic in compare or query-selection logic in the
  dev-loop.
- Do not bump artifact schema version.

## Design

Add a small tool-only helper:

```zig
pub const supported_event_taxonomy_version: u32 = 1;

pub fn appendTaxonomyVersionWarning(
    output: *std.ArrayList(u8),
    allocator: std.mem.Allocator,
    artifact_label: []const u8,
    event_taxonomy_version: ?u32,
) std.mem.Allocator.Error!void;
```

The helper appends this line only when `event_taxonomy_version` is present and
greater than `supported_event_taxonomy_version`:

```text
warning: <label> event_taxonomy_version=<n> newer than supported=1; event-kind role semantics may be incomplete
```

Each tool keeps its existing `Artifact` shape but adds:

```zig
event_taxonomy_version: ?u32 = null,
```

`causal-query` includes the warning near the top of its query output. The
dev-loop calls a no-warning query variant internally and emits one warning at
the top of the query report instead of repeating it for every selected query.

`causal-compare` emits separate warnings for `before` and `after` artifacts
when either side is newer than supported.

## Compatibility

Legacy artifacts without `event_taxonomy_version` remain valid and quiet.
Version `1` artifacts remain valid and quiet. Newer versions are still parsed
because the tools use `ignore_unknown_fields = true`; the warning only tells the
agent that role-based conclusions might be incomplete.

## Acceptance Criteria

- `causal-query` tests prove future taxonomy artifacts emit a warning.
- `causal-compare` tests prove future taxonomy artifacts emit before/after
  warnings.
- `causal-loop` tests prove query reports emit a single future-taxonomy warning.
- Existing versioned and legacy artifact tests continue to pass.
- Dogfood dev-loop artifacts generated by the current runtime remain quiet
  because they use taxonomy version `1`.

## Future Directions

- Add string-level `eventKindTaxonomy(kind: []const u8)` helpers for tools.
- Make compare finding-count logic explicitly role-aware once string taxonomy is
  available.
- Add taxonomy compatibility checks to CI artifact upload or retention tooling.
