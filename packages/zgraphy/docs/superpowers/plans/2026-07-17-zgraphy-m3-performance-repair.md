# zgraphy M3 Performance Repair Implementation Plan

1. Register the profile-derived source boundaries and this design under the
   existing `m3-exit-qualification` scenario.
2. Add a failing NenDB test proving production maxima do not cause production-
   maximum allocation, geometric growth preserves exact topology/indexes, and
   configured limits still fail closed.
3. Implement transactional lazy node/vector/edge column growth and run focused
   NenDB, store, delta, origin and M3 tests.
4. Measure the same self-host one-file process and retain before/after elapsed
   and peak-RSS diagnostics without promoting a claim.
5. Add a failing differential test requiring prepared RPC continuity to equal
   standalone source resolution while rejecting corpus/product mismatch.
6. Implement prepared parser/resolver reuse in `rpc_continuity` and route the
   repository indexer through it; retain standalone behavior.
7. Add failing origin tests for large exact coverage, duplicate rows, unknown
   owners and missing records, then replace construction/coverage scans with
   bounded hash indexes.
8. Re-profile and address any newly dominant complete-publication work without
   suppressing validation or weakening the M3.9 contract.
9. Add a failing deterministic scenario proving an appended Zig comment
   publishes a distinct current source generation with an unchanged semantic
   generation, graph/index identity, zero-operation delta, one reparse and no
   graph/origin deserialization; prove a changed declaration falls back to a
   full build.
10. Add extraction-cache semantic projection comparison, a validated
    identity-delta writer, schema-v7 semantic artifact bindings and streaming
    artifact verification.
11. Publish the source-only successor transactionally, retain its semantic
    dependency, remove the CLI's redundant graph reload, and prove restart,
    retention, corruption fallback and clean-build equivalence.
12. Rebuild ReleaseSafe and run the two-warmup/seven-retained paired Graphify
   qualification until both targets pass or the current measured deficit
   identifies the next required architectural slice.
13. Only after a passing receipt, promote performance evaluation evidence and
    run the requirement, M3 aggregate, full project and handoff gates.
